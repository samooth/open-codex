# OpenCodex Docker Usage

This document outlines how to use OpenCodex with Docker, covering both building the image from source and running a pre-built version.

## Prerequisites

- [Docker](https://docs.docker.com/get-docker/) installed and running on your system.
- An API key for your chosen AI provider (e.g., OpenAI, Google Gemini).

## 1. Running OpenCodex with a Pre-built Image

The provided `Dockerfile` is designed to install a pre-built `codex.tgz` package. This is useful for deploying a specific, tested version of OpenCodex.

### 1.1. Build the Docker Image

From the root of the `codex-cli` directory, ensure you have a `dist/codex.tgz` file (which is typically generated by running `npm run build` or similar build command). Then, build the Docker image:

```bash
docker build -t opencodex .
```

This command builds the Docker image and tags it as `opencodex`.

### 1.2. Prepare your Environment

You will need to provide your AI provider's API key to the Docker container. The recommended way is to use a `.env` file or pass it as an environment variable.

Create a file named `openai.env` (or similar) in your project directory (the directory you'll be mounting into the container) with your API key:

```
# openai.env
OPENAI_API_KEY=sk-YOUR_ACTUAL_OPENAI_API_KEY
```

If you are using a different provider, the environment variable name might change (e.g., `GOOGLE_API_KEY`).

### 1.3. Run the Docker Container

Mount your local project directory into the container, provide your API key, and then run OpenCodex.

```bash
docker run --rm -it \
  -v "$(pwd):/app" \
  --env-file openai.env \
  opencodex "Your OpenCodex prompt here"
```

**Explanation of the command:**

- `--rm`: Automatically removes the container and its file system when the container exits.
- `-it`: Runs the container in interactive mode and allocates a pseudo-TTY, allowing you to interact with the CLI.
- `-v "$(pwd):/app"`: Mounts your current host working directory (where your project files are) to the `/app` directory inside the container. This allows OpenCodex to read and write to your project files.
- `--env-file openai.env`: Passes environment variables defined in the `openai.env` file to the container.
- `opencodex`: The name of the Docker image you built.
- `"Your OpenCodex prompt here"`: Your prompt for OpenCodex, along with any other CLI flags (e.g., `--model gpt-4o-mini`).

**Alternative: Passing API Key Directly**

You can also pass the API key directly as an environment variable:

```bash
docker run --rm -it \
  -v "$(pwd):/app" \
  -e OPENAI_API_KEY="sk-YOUR_ACTUAL_OPENAI_API_KEY" \
  opencodex "Your OpenCodex prompt here"
```

### 1.4. Persisting Configuration and Memory

OpenCodex stores its configuration and semantic memory in a user-specific directory (typically `~/.open-codex`). To persist this data across container runs, you can mount a local directory for this purpose:

```bash
mkdir -p ~/.open-codex-docker-data

docker run --rm -it \
  -v "$(pwd):/app" \
  -v "$HOME/.open-codex-docker-data:/root/.open-codex" \
  --env-file openai.env \
  opencodex "Your OpenCodex prompt here"
```

This will store the `.open-codex` directory data from inside the container to `$HOME/.open-codex-docker-data` on your host machine.

## 2. Building and Running from Source (for Development)

If you want to build and run OpenCodex directly from source within a Docker container (e.g., for development or testing changes to the build process), you can create a custom `Dockerfile` or modify the existing one to include the build steps.

**Example `Dockerfile` for building from source (conceptual):**

```dockerfile
# (This is a conceptual example, not the existing Dockerfile)
FROM node:20-slim

WORKDIR /app

COPY package.json package-lock.json ./
RUN npm ci

COPY . .

RUN npm run build # Or your specific build command to generate dist/cli.js

ENTRYPOINT ["node", "dist/cli.js"]
```

**To use such a Dockerfile:**

1.  Place the above `Dockerfile` (or your modified version) in the root of your OpenCodex repository.
2.  Build the image: `docker build -t opencodex-dev .`
3.  Run the container: `docker run --rm -it -v "$(pwd):/app" --env-file openai.env opencodex-dev "Your prompt"`

**Note:** The existing `Dockerfile` is optimized for a pre-built `codex.tgz`. For development, it's often more practical to develop locally and then use Docker for deployment or specific testing scenarios.

## Important Considerations

- **Permissions:** Ensure the Docker container has the necessary permissions to read and write files in your mounted project directory.
- **Network Access:** Verify that your Docker container has network access to reach the AI model's API endpoints.
- **Resource Limits:** For very large codebases or complex AI tasks, you might need to allocate more CPU or memory to your Docker container.
